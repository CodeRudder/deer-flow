④ 使用说明

添加一个模型

  1. 登录 http://192.168.2.10:3000，点左下角 ⚙ Settings and more → Settings
  2. 左侧选 Models → 右上角 Add model
  3. 填 名称（自己起，唯一）、模型 ID（服务商的模型代号）、API Key
  4. 服务商下拉选对应供应商，Base URL 会自动填好；用私有网关才需要改
  5. 需要思考能力就勾上「该模型支持思考」，然后点检测确认
  6. 点 Save —— 立即生效，不用重启服务

服务商与 Base URL

每个服务商写进配置的键名不同，界面已自动处理，你不需要关心：

服务商写入的键需要填 Base URL
OpenAI / 其他兼容openai_api_base用私有网关时填
Anthropic Claudeanthropic_api_url用兼容端点时填
Google Geminibase_url一般留空
豆包 / DeepSeek / Kimiapi_base默认已填好
为什么 Base URL 不能乱填：填错键名不会在保存时报错，配置能正常存下去， 但第一次对话时才失败。新版已加校验——写错会被直接拒绝并提示正确键名。

「关闭思考时发送什么」怎么选

思考被关掉时有两条路：要么主动告诉端点「别思考」，要么什么都不说， 让端点按自己的默认行为走。默认是前者 —— 大部分原生服务商都认这一套。

但兼容端点不保证认。遇到下面任一种情况，就选「不发送任何禁用参数」：

  • 请求直接被拒：400 Upstream bad request: thinking.type `disabled` is not supported by this model。
  • 发了也白发：端点接受了禁用参数，返回里照样有思考块。
为什么这一项比看上去重要。「不思考」的请求不只来自你在聊天里关掉思考 —— 子代理执行、标题生成、记忆更新、安全扫描、追问建议这几条内部链路固定以 「不思考」发起。所以端点一旦不接受禁用信号，表现会是「子代理莫名其妙 400」， 而不是「关思考时报错」，很容易查错方向。选「不发送」这几条链路一并恢复。
代价要说清楚：选了「不发送」之后，关掉思考不再等于真的不思考 —— 端点很可能照常思考，只是不再因为参数被拒。对内部链路来说，这是「能跑」与「跑得快」之间的取舍， 目前选「能跑」。聊天里的思考开关此时是摆设，与检测结果里那条是一致的。
务必点一次「检测」。不同服务商对思考参数的支持差别很大，实测发现 某些兼容端点不传思考参数也会思考、传「关闭」也照样思考、思考预算填多大都一样。 检测会如实告诉你这个端点的真实行为——包括「关闭思考其实不生效」这种情况， 免得你以为开关管用，实际是摆设。

常见问题

保存后要重启服务吗？ 不用。配置文件是热重载的，下一次对话就生效。

能用手改 config.yaml 吗？ 托管区（标记符之间）会被界面整体重写， 别手改；托管区之外的内容界面不碰，可以放心手写高级配置——比如 when_thinking_enabled 的进阶写法。界面上编辑这类条目时会原样保留。

改坏了怎么办？ 每次保存都会自动备份为 config.yaml.bak.<时间戳>（保留最近 10 份）：

Get-ChildItem D:\deer-flow\src\config.yaml.bak.* | Sort-Object LastWriteTime -Descending
Copy-Item D:\deer-flow\src\config.yaml.bak.<时间戳> D:\deer-flow\src\config.yaml -Force

API Key 会明文显示吗？ 不会。列表和编辑框只显示掩码（sk-****1234）， 密钥存在 .env 里，配置文件只留引用。
