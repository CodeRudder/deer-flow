# DeerFlow 移动端网页 — 功能清单

> 范围：**核心优先**。对话、产物预览、智能体、设置随行；管理后台（用量/额度/
> 会话追踪/用户管理）留在桌面端 —— 密集表格与图表在手机上体验天然受限，
> 且是低频的运维操作。

## 0. 判断依据：手机端真正的高频动作

移动端不是「桌面功能搬小」。用户掏出手机的场景基本是两类：

- **问一句** —— 走在路上补一个提问、看进度、追一句
- **看一眼** —— 结果出来了，打开看产物/图片，然后转发或下载

据此，凡是「配置一次、长期不动」的（渠道、技能、MCP 工具）降级或移除；
凡是「读」的（对话、产物）做深做顺；凡是「写」的（发消息、回答澄清）优先做顺手。

## 1. 功能清单

### 1.1 对话（P0，核心）

| # | 功能 | 桌面现状 | 移动端要求 |

| C2 | 新建会话 | 侧边栏按钮 | 底部主导航「+」直达；欢迎页保留 |

### 1.6 明确不做（本阶段）

- 管理后台四个标签页（用量概览、额度管控、会话追踪、用户管理）
- MCP 工具配置、技能安装/创建、模型增删改、渠道绑定
- 文档站 `/[lang]/docs`、博客 —— 移动端不优化，保持可用
- 桌面端专属：多栏拖拽、悬停提示、键盘快捷键

## 2. 移动端必须解决的结构性问题

这些不是「缩小」，是形态要换。逐条对应到原型：

| # | 问题 | 现状 | 目标形态 |
|---|---|---|---|
| M1 | 产物面板是拖拽分栏 | `chat-box.tsx` 里 `ResizablePanelGroup` | 全屏页 / 底部抽屉，顶部有返回 |
| M2 | 顶部图标按钮拥挤 | 标题 + 会话状态 + Token + 额度 + 导出 + 产物（6 个） | 保留标题，其余收进「⋯」溢出菜单 |
| M3 | 输入框底部一行塞 6 个控件 | 模式/图片/视频/推理强度/模型/发送 | 主行：附件 + 输入 + 发送；其余进「+」面板 |
| M4 | 悬停才出现操作按钮 | `opacity-0 group-hover:` | 长按出操作菜单，或常驻小图标 |
| M5 | 无安全区适配 | 无 `viewport-fit`、无 `env(safe-area-inset-*)` | 刘海屏/手势条避让 |
| M6 | 输入框自动聚焦弹键盘 | `autoFocus` | 移动端默认不聚焦（避免一进页面键盘遮半屏） |
| M7 | 100vh 在移动浏览器地址栏收缩时跳动 | 常规 `h-screen` | `100dvh` |
| M8 | 会话列表靠侧滑抽屉 | `ui/sidebar.tsx` 的 Sheet | 保留抽屉（够用），但改为全屏宽 |

## 3. 断点与设备基线

| 项 | 取值 | 说明 |
|---|---|---|
| 基准宽度 | **390px**（iPhone 14/15） | 原型按此出图 |
| 最小支持 | 360px（安卓主流） | 不出现横向滚动 |
| 断点 | `< 768px` 为移动端 | 复用现有 `useIsMobile`（768px） |
| 平板 | 768–1024px | 沿用桌面布局，不单独设计 |
| 横屏 | 支持，但产物/视频类提示「横屏体验更佳」 | 不强制锁定 |
| 触控目标 | ≥ 44×44px | Apple HIG 下限 |
| 字号 | 正文 ≥ 15px，输入框 ≥ 16px | **iOS 上输入框 < 16px 会触发自动放大** |
