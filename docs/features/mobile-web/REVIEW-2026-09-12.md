## 1. 接口报错的根因（✅ 已实测确认）

浏览器里看到的接口报错**不是移动端代码的问题**，是两个环境问题叠加：

### 1.1 Gateway（8001）没有启动

- 直连 `http://localhost:8001/docs` 失败；经 Next 代理的 `/api/user/current` 返回 500。
- **启动失败原因**：`config.yaml` 引用了 4 个环境变量，本机 shell / `.env` 均未定义，
  Gateway lifespan 直接 `RuntimeError` 退出：

  ```
  RuntimeError: Failed to load configuration during gateway startup:
  Environment variable OPENAI_IMAGE_AUTHORIZATION not found for config value $OPENAI_IMAGE_AUTHORIZATION
  ```

  涉及变量（config.yaml 138/148/159/174 行）：
  `$QWEN_IMAGE_API_KEY`、`$OPENAI_IMAGE_API_KEY`、`$OPENAI_IMAGE_AUTHORIZATION`、`$MINIMAX_VIDEO_API_KEY`

- **临时处置**：已用占位值启动 Gateway（图片/视频生成功能不可用，其余正常）。
  **待办**：把真实值写入启动环境（`.env` 或 shell profile），否则下次启动仍会失败。

### 1.2 3000 端口跑的是 E2E 测试服务器，不是开发栈

- `lsof` + `ps` 确认 3000 上的 `next-server (v16.2.6)` 是 **`pnpm test:e2e` 的 webServer**
  （Playwright 配置 `DEER_FLOW_AUTH_DISABLED=1` 启动，且当时正有 `pnpm test:e2e` 进程在跑）。
- 后果：
  - 服务端守卫被绕过 —— `/workspace` 307 → `/workspace/chats/new`，**永远不会跳登录页**；
  - 客户端 API 请求直接打到真实 Gateway，全部 **401 Unauthorized**，且前端 API client
    在控制台反复重建（`Creating API client...` 刷屏循环）。
  - 401 接口清单（控制台实测）：`/api/threads/search`、`/api/langgraph/threads/search`、
    `/api/models`、`/api/quotas/me`、`/api/skills`、`/api/channels/providers`、
    `/api/suggestions/config`、`/api/image-generation/providers`、
    `/api/video-generation/providers`、`/api/threads/{id}/subagents`。
- **结论**：在这套进程上手工走查页面，看到的多是「未登录 + 空数据」态，不能作为评审依据。
- **待办**：评审/联调用真实栈（`make dev` 或另起 `pnpm dev` + 已启动的 Gateway），
  不要与 E2E 共用 3000。

### 1.3 登录问题（⏳ 中断时未解决）

- 本地库 `backend/.deer-flow/data/deerflow.db` 只有一个账号：
  `admin@sz-jlc.com`（system_role=admin，account_status=active，needs_setup=0）。
- 记忆中的密码 `Gdw@1234` 是 **Windows 测试机（192.168.2.10）** 的，本地库密码未验证。
- 尝试 `POST /api/auth/login/local` 返回 `401 not_authenticated`（登录接口本身被拦），
  路由前缀或网关鉴权中间件行为待核实 —— **此线中断，未完成登录**。
- ⏳ 登录打通后需实测：登录页渲染（T3）、真实会话列表、真实对话流。

### 1.4 手机模式判定的 UA 注意点（✅ 已实测确认）

- `/m/*` 分流由 `src/lib/device.ts` **纯 UA 判定**，与视口宽度无关；
  且 `headlesschrome` 被列入爬虫 → 桌面树。
- Playwright/自动化默认 UA（HeadlessChrome）进的是**桌面树**——本次实测页面
  `Toggle Sidebar` 桌面布局即由此来。人工评审：
  - Chrome DevTools 设备模式会改 UA → 正常进 `/m/*`；
  - 或直接访问公开路径 `/m/workspace`（已验证 200，可绕过 UA 判定，适合自动化走查）。

### 6.4 本次评审的方法论教训

§5.1 的「真机复测 12 项全通过」**有洞**：测尺寸时是**从会话页软导航**到产物页的，
此时 `chat-surface.css` 这个 chunk 还在，量到的 44px 行高是真的；但用户直接打开
产物链接时那份 CSS 根本不在。**几何断言必须在目标路由上冷启动**（直接 `goto`
该 URL），不能靠站内导航过去 —— 否则测的是「缓存还在」而不是「页面本身对」。
