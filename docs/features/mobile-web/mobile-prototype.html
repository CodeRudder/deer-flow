原型里体现的结构性改动（对应功能清单 §2）

#桌面现状移动端形态出现于
M1产物是可拖拽的 60/40 分栏（ResizablePanelGroup）全屏页 + 底部操作条⑤
M2顶部 6 个图标按钮（状态/Token/额度/导出/产物…）只留标题，「⋯」溢出菜单②
M3底部一行塞 5 个控件（模式/图片/视频/推理强度/模型）输入区底部常驻「模式 / 模型」pill，点击直接切换；其余进「＋」面板② ③
M4消息操作 opacity-0 group-hover:，触屏没有 hover操作条常驻；列表行改长按菜单② ①
M5无 viewport-fit、无安全区变量env(safe-area-inset-bottom) 用于标签栏/输入区/操作条全部
M6输入框 autoFocus移动端默认不聚焦（否则键盘一进页面遮半屏）②
M7h-screen 在地址栏收缩时跳动100dvh全部
M8侧边栏抽屉承载导航底部标签栏 + 根屏幕（对话/智能体/设置）① ⑥ ⑦

两处待你定夺

1. 底部标签栏 vs 侧边抽屉。原型按标签栏出图（手机原生范式，智能体与设置一键可达）。 若你希望与桌面信息架构严格一致，可改回全屏抽屉 —— 但标签栏在多一层功能时更省一次点击。

2. 产物是「全屏页」还是「底部抽屉」。原型按全屏页出图。 全屏利于看 HTML 报告与图片；底部抽屉的好处是能一边看对话一边看产物。二者可后续按产物类型分：图片走灯箱、HTML 走全屏。
